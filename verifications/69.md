# Verification: ci: speed up the E2E job

## Change

The E2E job, CI's critical path, drops from 130–150s to about 85s, so CI's wall clock goes from ~2m15s–2m45s to ~1m25s. Supabase starts first in the background (without Studio and postgres-meta), the app builds while it starts, Playwright installs only Chromium's headless shell, and the specs run against the prebuilt app (`scripts/dev-local.sh --prebuilt`) instead of `next dev`. `--prebuilt` refuses a build whose inlined Supabase URL isn't the local stack's.

## Checks

- `npm run lint`: clean
- `npx tsc --noEmit`: clean
- `npm run test:run`: 24 files, 318 tests passed
- `NEXT_PUBLIC_SUPABASE_URL=https://example.supabase.co SUPABASE_SERVICE_ROLE_KEY=dummy npm run build`: compiled successfully
- `npx prettier --check` on the changed workflow, config, and docs: clean
- CI on this branch: all checks green; per-run timings below.

## Behavior

All local runs used an isolated stack (see Harness gaps) on API port 55321 and app port 3100, so the shared stack and the dev server on :3000 were untouched.

### Supabase without Studio and postgres-meta still serves the specs and type check

`npx supabase start -x studio,postgres-meta` started db, rest, auth, and kong. `npm run db:types:check` printed `server/database.types.ts is up to date.`, and `docker events` during it showed no container starting (only kong health checks), so type generation doesn't need postgres-meta. With `-x studio,gotrue,postgres-meta` instead, `supabase status -o env` printed only `API_URL DB_URL GRAPHQL_URL REST_URL`, with no `SERVICE_ROLE_KEY`, which `dev-local.sh` needs. So Auth stays.

Before the fix, the specs failed at server start: `scripts/dev-local.sh: line 30: LOCAL_STUDIO_URL: unbound variable`. After it: `8 passed`.

### Headless shell alone runs the specs

With `PLAYWRIGHT_BROWSERS_PATH` pointing at a fresh directory, `npx playwright install --only-shell chromium` installed only `chromium_headless_shell-1243` and `ffmpeg-1011`, and `npx playwright test`: `8 passed (11.5s)`. In CI, apt under `--with-deps` had installed only extra fonts; every required library was "already the newest version".

### Prebuilt server and its guard

- Built with only `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:55321` (no service key, no `AUTH_SECRET`, as CI does), then `E2E_PREBUILT=1 npx playwright test`: `8 passed (6.6s)`. Without it (`next dev`): `8 passed (9.6s)`.
- Built with `https://example.supabase.co`, then `scripts/dev-local.sh --prebuilt`:
  ```
  Refusing to start: .next was not built with NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:55321.
  exit=1
  ```

### `scripts/ci-background.sh` passes through the result

With `RUNNER_TEMP` set to a temp dir: `start ok bash -c 'sleep 2; echo "hi there"'` returned immediately; `wait ok` printed `hi there` and exited 0. `start bad bash -c 'echo boom >&2; exit 3'`, then `wait bad` printed `boom` and exited 3.

### CI timings on this branch

E2E job, in seconds:

| Commit                                                 | Runs                               |
| ------------------------------------------------------ | ---------------------------------- |
| Baseline (main, before)                                | 132, 132, 148, 157, 228            |
| Background Supabase, no Studio/pg-meta, headless shell | 99                                 |
| + prebuilt server (test step 24s → 11s)                | 92, then reruns 98, 90, 104        |
| + Supabase before `npm ci` via `supabase/setup-cli`    | 92, then reruns 81, 82, 88, 78, 78 |

Starting Supabase before `npm ci` looked worse on its first run (92s), so the reruns of both commits alternated to compare them: mean ~96s without it and ~84s with it.

## Not verified

- The Migration compat job is unchanged here. It runs main's `dev-local.sh`, which crashes without Studio until this merges, so its speedup comes in a follow-up PR.
- Timings come from 4–6 runs per variant on shared GitHub runners, which vary by ±10s run to run. The mean is the claim, not any single run.
- If a future `ubuntu-latest` image drops a library Chromium needs, the browser fails to launch. That would be a loud failure, not a silent one, and the fix is to restore `--with-deps`.

## Harness gaps

- The `verify-locally` skill says every checkout shares one local stack. To test CI's Supabase flags without disturbing the running stack and the dev server on :3000, I changed `project_id` and the ports in `supabase/config.toml` and the port in `playwright.config.ts` locally (never committed). A supported way to run a second stack would help.
- Background-step logs are printed when `ci-background.sh wait` runs, so their GitHub timestamps don't show where inside `supabase start` the time goes.
