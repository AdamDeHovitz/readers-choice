# Verification: feat: subscribable calendar feed per club member

## Change

Club members can subscribe to their club's meetings from the Schedule tab. Each member gets a personal feed URL (`/api/calendar/<token>.ics`) that works without a session, stops working when they leave the club or reset it, and updates events in place when meetings change.

## Checks

- `npm run lint`: clean
- `npx tsc --noEmit`: clean
- `npm run test:run`: 347 passed (new: `lib/ics.test.ts`, `lib/club-calendar.test.ts`, `server/calendar.test.ts`, `app/actions/calendar.test.ts`)
- `npm run db:reset`, then `npm run db:types:check`: "server/database.types.ts is up to date."
- `npm run build` (dummy env): succeeded; route list includes `ƒ /api/calendar/[token]`
- `PORT=3100 npx playwright test`: 14 passed, including the 3 new specs in `e2e/calendar.spec.ts`

### The feed works without a session

`curl` (no cookies) to the URL: `200`, `content-type: text/calendar; charset=utf-8`, `cache-control: private, no-store`, no `set-cookie` (after excluding `/api/calendar` from the proxy matcher; before that, Auth.js set csrf and callback cookies). Parsed with the Python `icalendar` library:

```
calendar: Seed Club
2026-10-12T02:51:37+00:00 -> 2026-10-12T04:51:37+00:00 | Seed Club: The Remains of the Day
2026-11-13T02:51:37+00:00 -> 2026-11-13T04:51:37+00:00 | Seed Club (book TBD)
2026-11-17T02:51:37+00:00 -> 2026-11-17T04:51:37+00:00 | Seed Club (book TBD)
2026-11-25T02:51:37+00:00 -> 2026-11-25T04:51:37+00:00 | Seed Club (book TBD)
```

The fifth seed meeting (`…0005`) belongs to Other Club and is correctly absent. Long descriptions fold at 75 octets with leading-space continuations.

### Who can't

- Malformed token `/api/calendar/nope.ics`: `404`. Unknown well-formed token (43 × `x`): `404`.
- Removed bob from Seed Club with `db:sql`, then fetched his feed: `Not found 404`. Re-added him with his original `joined_at`, and the feed returned `200`.
- dave (not in Seed Club) on Seed Club's schedule: no "Add to calendar" button (`e2e/calendar.spec.ts` "non-members get no calendar link").
- Actions: `app/actions/calendar.test.ts` covers signed-out callers (rejected with no DB calls) and non-members (rejected after only the `members` lookup, before any token query) for both `getCalendarFeedToken` and `resetCalendarFeedToken`.

### e2e guard

`e2e/calendar.spec.ts` guards three claims: a member's dialog link serves a `text/calendar` feed to a cookieless request with Seed Club's meetings and not Other Club's; unknown tokens get a 404; non-members see no button.

## Not verified

- Subscribing in real Google Calendar or Apple Calendar. Google can't reach localhost, and its refresh delay makes a preview test slow. Format correctness rests on the `icalendar` parse and the unit tests. Worth subscribing once from production after merge.
- The Google `cid=webcal://…` one-click link opening Google's "Add calendar" dialog. I checked the URL's shape, not Google's handling of it.
- Time zone display in calendar apps. Events are written in UTC (`…Z`), which clients convert to local time.

## Harness gaps

- `playwright.config.ts` hard-coded `localhost:3000`, so specs couldn't target a worktree's server on another port while the main checkout's server held :3000. Fixed in this PR (`PORT` is honored), and the verify-locally skill mentions it.
- Killing a dev server mid-compile left `.next` in a state where `npm run build` failed with `next/font/google queries have exactly one entry`. `rm -rf .next` fixed it. Already covered loosely by the skill's "Build fails right after many file changes" pitfall.
