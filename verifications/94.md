# Verification: fix: book search finds exact titles that stemming buried

## Change

Book search (`packages/core/open-library.ts`) now finds exact titles that Open Library's stemming buried, such as *The Disappearers* by Marlon James, and title + author queries such as "intermezzo sally rooney". It runs an unstemmed `title_suggest` query beside the general `q=` query, then ranks results by how well the title matches. Members can now find and nominate these books.

- `npm run test:run`: 42 files, 427 passed. `open-library.test.ts` has 16 tests, using fixtures re-recorded from the live API with the exact requests the new code sends.

### Failure paths

Covered by unit tests with a stubbed `fetch`:
- The exact-title query throws: results still come from the general query.
- The general query returns 503: *The Disappearers* still comes from the exact-title query.
- Both fail: `[]`, which the form shows as "No books found".
- A blank or punctuation-only query (`" ?! "`) makes no request.
- Quotes in the query are stripped from the `title_suggest` phrase.

## Not verified

- **Failure path in the running app.** The search runs server-side, so I couldn't block Open Library from the browser. The fallbacks are covered only by the unit tests above.
- **Partial words and typos.** "the disappe" returns unrelated books and "disapearers" returns *Disapearing*-misspelled titles. The old code behaved the same: Open Library has no prefix or fuzzy title matching on these endpoints. Members have to type whole words.
- **Shared-word titles.** When Open Library's top general result shares no words with the query, it ranks as an exact match. A wrong top result from Open Library would therefore come first. None of the 31 table queries or the extra queries above showed this.
- **Author display.** "Kafka on the Shore" ranks first, but its author shows as 村上春樹, which is the only name Open Library lists. The old code showed it the same way.
- **Edit-meeting and log-past-meeting dialogs.** They use the same `BookSearch` and action, but I didn't open them.
