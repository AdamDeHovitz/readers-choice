# Verification: ci: speed up the Migration compat job

## Change

The Migration compat job (runs only when `supabase/migrations/` changes) gets the same speedups #69 gave E2E, and drops from 140–148s to about 85s. Supabase starts first in the background with main's CLI version and without Studio and postgres-meta. Main's app builds while it starts, only Chromium's headless shell installs, and main's specs run against the build (`E2E_PREBUILT=1`).

## Checks

- `npx prettier --check .github/workflows/ci.yml`: clean
- `jq -r '.packages["node_modules/supabase"].version' package-lock.json` (the step that picks main's CLI version): `2.120.0`
- CI on this branch: all checks green (run linked below). Only `.github/workflows/ci.yml` and docs differ from main (`git diff origin/main --stat`).

## Behavior

### Migration compat passes and is faster

This PR changes no migrations, so the job would normally be skipped. A temporary commit made "Migrations changed?" always report `true`, then a later commit reverted it.

- Run [42928268468](https://github.com/AdamDeHovitz/readers-choice/actions/runs/42928268468): Migration compat passed in 85s. Steps: setup-cli 5s, setup-node 16s, npm ci 13s, headless shell 9s, wait for Supabase 22s, main's specs 10s.
- Run [42928528336](https://github.com/AdamDeHovitz/readers-choice/actions/runs/42928528336): Migration compat passed in 83s. Wait for Supabase 7s, wait for the build 2s, main's specs 13s. E2E 86s.
- Before (runs 42744292381, 42738331491): 140s and 148s.

### The prebuilt guard caught a bad build in CI

In run 42928268468, E2E failed: `git commit -a` had swept my local-only `supabase/config.toml` (API port 55321) into the temporary commit, and `dev-local.sh --prebuilt` refused to serve the build:

```
[WebServer] Refusing to start: .next was not built with NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:55321.
```

The next commit restored both files from main, and E2E passed in the following run.

## Not verified

- After the TEMP revert, Migration compat is skipped again on this PR. Its passing runs used this job definition with the force in place. The revert only restores the original `git diff --quiet` line.
- The setup-cli `version` input with main's lockfile version was exercised only with 2.120.0, which is also the PR's version. A PR that bumps the CLI wasn't tested.

## Harness gaps

- Run 42928528336's Build job (not changed here) failed once with `Can't resolve '@vercel/turbopack-next/internal/font/google/font'` while fetching Playfair Display from Google Fonts, and passed on rerun. Builds that fetch `next/font/google` at build time can flake on network hiccups, and the background builds in E2E and Migration compat share that risk.
- The temporary-commit trick is the only way to exercise Migration compat on a PR without migrations; a `workflow_dispatch` input or label would make it easier.
