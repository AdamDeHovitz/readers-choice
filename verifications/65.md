# Verification: feat: verification loop (verifications/<pr>.md gate)

## Change

A ready PR now needs `verifications/<pr-number>.md` with all five sections filled in, or the **Verification** check fails. Drafts only get a warning. Agents get the loop, evidence standards, and recipes in `verifications/README.md`. `npm run db:sql` now works on a machine without `psql`.

## Checks

- `npm run lint`: 0 errors, 11 warnings (all in existing TS files; this PR changes no TS)
- `npx tsc --noEmit`: clean
- `npm run test:run`: 17 files, 294 tests passed
- `next build` with dummy env: succeeded
- `npm run test:e2e`: not run locally (see Not verified). CI's E2E job runs it on this PR.
- shellcheck and actionlint: not installed, not run.

## Not verified

- Whether this changes how often agents verify or how good their evidence is. Only later PRs can show that; `scripts/verification-gaps.sh` and the files themselves are the data.
- Local e2e: port 3000 was held by another checkout's dev server, and `playwright.config.ts` reuses whatever is on 3000, so a local run would have tested other code. This PR changes no app code; CI's E2E job covers it.
- `db:sql` via a host `psql` (not installed here).
- The check isn't a required status check in branch protection, so it doesn't block a merge. That's a repo settings change for you to decide.
- The README's recipes by change type (other than the voting example and the `db:sql` steps) are written from the code and existing specs, not each run end to end.

## Harness gaps

- `npm run db:sql` needed a host `psql` the setup docs never mention. Fixed in this PR.
- `playwright.config.ts` hardcodes port 3000 with `reuseExistingServer`, so with several worktrees `npm run test:e2e` can silently test another checkout's server. It should read `PORT` the way `dev:local` does.
- All worktrees share one local Supabase stack, so verifying in one can disturb another (now noted in `AGENTS.md`).
