# Verification: feat: verification loop (verifications/<pr>.md gate)

## Change

A PR marked ready for review now needs `verifications/<pr-number>.md` with all five sections filled in, or the **Verification** check fails. Drafts only get a warning. The check's run also warns when a PR changes the check itself, or when files changed after the verification file was last updated. Agents get the loop, evidence standards, and recipes in `verifications/README.md`, pointed to from `AGENTS.md` and the `verify-locally` skill. In `npm run db:sql`, a failing statement now makes it exit non-zero, and redirected output is clean.

An adversarial review subagent did three rounds; the third found no blockers or should-fixes. Everything it reproduced is fixed below, except where noted under "Not verified". Round 2 caught a blocker that I had introduced while fixing round 1 (see the template rows below).

While this PR was open, #66 merged into main. It slimmed `AGENTS.md`, moved procedures into skills (`.agents/skills/verify-locally`), and added its own `scripts/db-sql.sh` with a container fallback. I merged main in:
- `AGENTS.md` is main's version plus a three-line "Verifying work" section. The local-testing notes I had added (PORT, shared stack) moved to where main now keeps them: the `verify-locally` skill already covers PORT, so I added only the shared-stack reset rule as a Pitfall, plus a "Record it" step pointing at the verification file.
- `scripts/db-sql.sh` is main's version plus this PR's TTY handling and `ON_ERROR_STOP`.
- `docs/ci-and-previews.md` lists the Verification check.
The review rounds ran before this merge, so they didn't see these edits.

## Behavior

### Check script, on the review's edge cases

All are in `scripts/check-verification.test.ts`, which runs the real scripts on files in a scratch directory. One parser, `scripts/verification-sections.pl`, now does all the markdown handling for both scripts. Before, a perl regex and an awk script disagreed about code and comments.

| Input | First version | Now |
| --- | --- | --- |
| complete file | pass | pass |
| no file | fail: `Missing verifications/7.md` | same |
| `../verifications/7` as the PR | passed, read the file | exit 2, usage error |
| section with only template comments | fail | fail: `"## behavior" is empty` |
| section with only `-`, `---`, `> .`, `### Sub` | pass | fail: empty |
| `<!-- oops` never closed | pass (GitHub hides the rest of the file) | fail: `unclosed <!--` |
| CRLF line endings | fail: all five "missing" | pass |
| `## checks ##` | fail: missing | pass |
| `## Checks` only inside a code fence | counted as the section | fail: `missing section "## checks"` |
| `# reproduce` shell comment in a fence | could empty the section | pass |
| `## Change` twice | later one won | fail: `appears 2 times` |
| `<!--` inside inline code or a fence | n/a | pass (GitHub shows it as text) |
| untouched `TEMPLATE.md` | fail: five "empty" | same, with no "unclosed" error |
| template filled in, guidance comments kept | pass | pass |
| comment spanning lines, `<!-->` | pass | fail as empty / pass, as on GitHub |
| ``` inside `~~~`, a "```sh" line inside a fence, 4-space-indented ```, inline ```code``` | n/a | pass: none of them opens or closes a fence |
| `   ## Checks` (indented 1–3 spaces) | fail: missing | pass |
| a stray `<!--` mid-sentence, never closed | n/a | pass (GitHub shows it as text; checked by the reviewer via GitHub's markdown API) |
| `- <!--` never closed (starts a block) | n/a | fail: `unclosed <!--` (GitHub hides the rest) |
| `✅ 通過しました` as the only content | n/a | pass (was counted as empty) |

How the template rows came up: in round 1's fixes, the first draft of this file mentions `<!--` in inline code, and the new unclosed-comment check rejected it. My fix for that (e60f274) dropped multi-line comment stripping. Every file that kept the template's guidance comments then failed as "unclosed", including an untouched template. This file has no such comments, so CI stayed green. I had also written in this file that the untouched template fails with five "empty" errors without rerunning that check after the change. Round 2 caught it, and I reproduced it on the e60f274 scripts: both the untouched template and a filled one with comments gave `unclosed <!-- comment`. On the current scripts the filled one gives `all sections filled in.`

Run against this repo: `scripts/check-verification.sh 65` passes. The untouched-template result is now a test that reads the real `verifications/TEMPLATE.md`.

## Not verified

- Whether this changes how often agents verify, or how good their evidence is. Only later PRs can show that.
- The check is not a required status check, so `gh pr ready` and merging both still work while it's red. That's a branch-protection decision for you.
- A PR can still edit the checker so that it passes. It now gets a warning, not a block. Running main's copy of the checker would block it, but then a PR that legitimately changes the checker (like this one) would be judged by the old version.
- The gate checks structure only. A file of "None." passes, and the reviewer is the only check on quality.
- The weekly gaps review is a written instruction, with nothing scheduled to run it.
- Local e2e: port 3000 was held by another checkout's dev server, and `playwright.config.ts` reuses whatever is on 3000. This PR changes no app code; CI's E2E covers it.
- `db:sql` via a host `psql` (not installed here). That path only gained `-v ON_ERROR_STOP=1`.
- Fork PRs: the workflow is read-only and uses no secrets, so they should work, but none were tried.
- A merge from main followed by the stale-file warning, in real CI (only in a scratch repo).
- Parser nits from round 3, left as is. Each fails loudly or needs contrived input:
  - `<!--` inside code the parser doesn't recognize as code is wrongly reported as unclosed: a fence inside a blockquote, an indented code block, or inline code that wraps lines.
  - Content a reviewer can't see still counts: a bare link reference definition, `<div hidden>`, an escaped backtick before `<!--`.
  - A setext heading (`Checks` over `---`) is reported missing.
- The README's recipes by change type, other than the voting example and the `db:sql` steps, are written from the code and existing specs, not each run end to end.

## Harness gaps

- `npm run db:sql` needed a host `psql` the docs never mention. I fixed it here, and #66 fixed it on main independently; the merged script keeps main's version plus this PR's TTY and error-exit fixes.
- `playwright.config.ts` hardcodes port 3000 with `reuseExistingServer`, so with several worktrees `npm run test:e2e` can silently test another checkout's server. It should read `PORT` the way `dev:local` does.
- All worktrees share one local Supabase stack, so a reset in one wipes another session's state. The `verify-locally` skill now has one rule for when to reset.
- CI E2E can fail before running any test when the dev server can't fetch Google Fonts, and `supabase start` hit Docker Hub `toomanyrequests` (it retried and succeeded). Self-hosting the fonts or serving a production build in CI would remove the first; a registry mirror or image cache the second.
