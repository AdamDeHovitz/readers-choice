# Verification: fix: send a Google Books API key for the description fallback

## Change

When `GOOGLE_BOOKS_API_KEY` is set, `saveBook`'s Google Books description fallback sends it as `key=`, so it uses our own quota instead of Google's exhausted anonymous one. Without the variable, behavior is unchanged. Errors now include the HTTP status.

## Checks

- `npm run lint`: clean
- `npm run typecheck` (all workspaces): clean
- `npm run test:run`: 45 files, 437 passed. New tests in `packages/core/google-books.test.ts`:
  - `searchVolumes` sends `key` only when given one.
  - `findGoogleBooksDescription` sends it on both the ISBN and the title + author lookups.
- Build with dummy env: compiled successfully

## Behavior

### Keyless requests are refused today

Three keyless requests from my machine at 2026-11-13 02:57 UTC (18:57 Pacific, many hours into Google's quota day):

```
$ curl -s -o /dev/null -w "%{http_code} " -G "https://www.googleapis.com/books/v1/volumes" --data-urlencode "q=isbn:9780593320860"   # ×3
429 429 429
```

The response body names the quota: `Quota exceeded for quota metric 'Queries' and limit 'Queries per day' of service 'books.googleapis.com' for consumer 'project_number:624717413613'`. That consumer is Google's shared anonymous project, not ours. Vercel's production env has no Google Books key (I listed the variable names; none is for Books), so production makes the same keyless requests.

### The fallback without a key (production's current path)

A temporary integration test (deleted afterwards) called `findGoogleBooksDescription` live for _The Overstory_ with `GOOGLE_BOOKS_API_KEY` unset:

```
PROBE key=false description=null
PROBE error: Error searching Google Books: Error: Google Books API error: 429 Too Many Requests
PROBE error: Error searching Google Books: Error: Google Books API error: 429 Too Many Requests
```

It fails soft: `saveBook` still saves the book, without a description, and the log now carries the status code.
