## Change

`/privacy` is a public privacy policy, linked from the home page and the login screen, so Google's OAuth consent screen (and later the App Store) has a policy URL. It describes what the app stores, who sees it, the services involved, and how to request deletion.

### Claims checked against the code

- Account data: `users` holds `email`, `name`, `avatar_url`, `google_id` and `password_hash` (bcrypt; `server/password.ts`).
- Fellow members see email addresses: `getBookClubDetails` includes `email` only when the viewer is a member.
- Non-members see name, description and member count: the club page shows non-members only the name and description ("Invite required"), and `/browse` shows `memberCount`.
- Leaving a club: `removeMember` lets members remove themselves (`member-list.tsx`, "Are you sure you want to leave this book club?").
- Club deletion: `delete_book_club` raises `Only super admins can delete book clubs`, so the policy says "we can delete a whole club on request", not club admins.
- Rate limits: `rate_limits` keys are `scope:` + SHA-256 of the IP or email (`rateLimitKey`). No job deletes old rows, so the policy says they hold only hashes rather than claiming they expire.
- No analytics: no analytics, tracking or error-reporting packages are in `apps/web/package.json`, and no such code is in `app/`, `components/` or `server/`.
- Third parties: Open Library, Google Books and OverDrive calls send only search text, titles and library keys (`packages/core/open-library.ts`, `google-books.ts`, `libraries/overdrive.ts`).
