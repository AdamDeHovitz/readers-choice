# Verification: feat: serve operations over HTTP at /api/v1

## Change

`POST /api/v1/<operation name>` runs the same operations as the web's server actions, for clients that can't call server actions (the mobile app, #75). It refuses unknown names (404), foreign origins (403), non-JSON bodies (415), bad input (400) and signed-out callers (401). Writes through it revalidate the same web pages a server action would. `contract/client.ts` is a typed client for it. Viewers still come from the NextAuth session cookie.

### Unit tests

Covered by `app/_operations/http.test.ts`, which calls `handleOperationRequest` with real `Request` objects, the real operation registry and theme operations, and a fake database:

- `themes.nope` → 404 `{"success":false,"error":"Unknown operation: themes.nope","invalidate":[]}`
- `Origin: https://evil.example` → 403, with no database queries made
- Same-origin `Origin`, and no `Origin` at all → 200 `{"success":true,"data":[],"invalidate":[]}`
- `application/x-www-form-urlencoded` body → 415
- Body `{` → 400; `{"themeId":"1"}` → 400 `Invalid id`
- Signed out → 401 `Unauthorized`
- A non-member deleting a theme → 200 `{"success":false,"error":"You must be a member to delete themes"}`, and `revalidatePath` isn't called
- The submitter deleting it → 200 `{"success":true,"invalidate":[["club","22222222-…-000000000001","themes"]]}`, and `revalidatePath("/book-clubs/22222222-…-000000000001/themes")` is called
- `createOperationClient().call(contracts.themes.suggestTheme, …)` sends `POST https://…/api/v1/themes.suggest` with the caller's `authorization` header, and returns `{ success: true, data: { themeId }, invalidate: […] }`. A fetch that throws becomes `success: false` with the generic message.
