# Verification: feat: output schemas, error codes, contract snapshot and a rollout ratchet

## Change

Operation contracts declare an output schema, and the server parses every result through it, so clients get only declared fields. Every failure carries a stable `code`, and `/api/v1` derives its HTTP status from it (`internal` is now 500). A committed JSON Schema snapshot of the contracts fails CI on any API change, and ESLint stops new actions from using `runAction`. Members see no change.
