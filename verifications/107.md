# Verification: chore: EAS build config for TestFlight

## Change

Adds `apps/mobile/eas.json` (production profile, remote build numbers with auto-increment, `EXPO_PUBLIC_API_URL` pinned to production) and the Expo project ID in `apps/mobile/app.config.ts`. An operator can now run `eas build --platform ios --profile production --auto-submit` from `apps/mobile` to build and upload to App Store Connect. No change to the website or to app behavior.

## Checks

- `npx prettier --check apps/mobile/eas.json apps/mobile/app.config.ts`: clean
- `npm run typecheck`: clean
- `npm run lint`: clean
- `npm run export:ios -w @readers-choice/mobile`: bundled (one Hermes bundle, 3.4MB)
- Local Release build for the iOS Simulator (`expo prebuild` then `xcodebuild`): `BUILD SUCCEEDED`

## Behavior

- Ran `eas build --platform ios --profile production --auto-submit` from `apps/mobile` with this config, signed in as the owner's Apple account. EAS output: build ID `4ab1237f-fec9-4194-9faa-5f71aa570c88`, app version 1.0.0, build number 1, "Build finished", then "Your binary has been successfully uploaded to App Store Connect!"
- `eas init` created the Expo project `readers-choice` (ID `7cfd7bf1-a9f2-46f1-987d-6947e714b8a9`); it could not write to the dynamic `app.config.ts`, so the ID was added by hand under `extra.eas.projectId`. The build above ran with that value.

- After the project was transferred to the `readers-choice-llc` Expo org, added `owner: "readers-choice-llc"` to `app.config.ts`. `eas project:info` then reported `fullName  @readers-choice-llc/readers-choice`, ID `7cfd7bf1-a9f2-46f1-987d-6947e714b8a9`.

## Not verified

- That the build finished processing in TestFlight and installs on a device. Apple was still processing when this was written.
- That a build run after the transfer works (the one uploaded ran before it), and that the iOS credentials moved to the org with the project.
- That the installed app signs in and loads data against production.
- `npm run test:run` and the web build: no web or shared code changed.
- That `autoIncrement` yields build 2 on the next build (only build 1 has run).

## Harness gaps

- `expo prebuild` rewrites the `ios` script in `apps/mobile/package.json`, and `npm install` changed `package-lock.json`. Both were reverted by hand and are not in this PR.
- `pod install` fails without `LANG=en_US.UTF-8`.
