# Verification: Friendlier meeting date/time picking, local-time dates

## Change

Admins pick a meeting's date and time with a calendar and a 15-minute time list instead of the browser's minute-level datetime picker, and new meetings are pre-filled from the club's cadence. Reader-facing dates render in the viewer's time zone, so evening meetings no longer show on the next day.

## Checks

- `npm run lint`: clean
- `npx tsc --noEmit`: clean
- `npm run test:run`: 303 passed (new: `lib/meeting-defaults.test.ts`, more cases in `lib/datetime-input.test.ts`)
- `TZ=America/Los_Angeles` and `TZ=Pacific/Auckland` runs of those two files: 13 passed each
- `npm run build` (dummy env): compiled successfully
- `npm run test:e2e`: not run locally (see Not verified); CI runs it

Only the logged meeting moved.

## Not verified

- **Production rows the migration will touch.** A read-only count against production was blocked by permissions, so the number of affected rows is unknown.
- **`npm run test:e2e` locally.** Port 3000 was held by another server whose environment I couldn't confirm, and the config hard-codes 3000. CI's E2E job covers this.
- **The native time wheel on a real iPhone or Android.** Only Chromium was driven.
- **First paint before hydration** still shows the UTC date for a moment. That's by design: `LocalDate` swaps in local time on hydrate.

## Harness gaps

- `playwright.config.ts` hard-codes port 3000, so the e2e specs can't run against a worktree server on another port.
