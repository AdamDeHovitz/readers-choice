# Verification: refactor: keep lib/ isomorphic for the mobile app

## Change

Node-only code moved out of `lib/` so it can be shared with the planned React Native app (#75): bcrypt hashing → `server/password.ts`, invite-code generation → `server/invite-code.ts`, rate limiting → `server/rate-limit.ts`. The portable parts stay in `lib/` (`lib/credentials.ts`, `isWellFormedInviteCode`). ESLint now rejects Node built-ins and `bcryptjs` in `lib/`. Sign-in, registration, invite links and rate limiting behave exactly as before.

## Harness gaps

- `playwright.config.ts` hardcodes `baseURL` http://localhost:3000 with `reuseExistingServer`, so with other sessions on :3000, running specs against your own server takes a throwaway config override. An `E2E_BASE_URL`/`PORT` env var would make that a one-liner.
- The first e2e run against a fresh `next dev` can time out on cold route compiles. A warm-up request or `E2E_PREBUILT=1` avoids it.
