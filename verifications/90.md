# Verification: feat: mobile sign-in, session management and the API client

## Change

The mobile app signs in with email and password, keeps the session across restarts (refresh token in the keychain), refreshes access tokens one at a time, and signs out (revoking the session on the server). Any operation can be called with `sessions.call`. `/api/v1` now serves CORS without credentials, so bearer requests work from other origins, while cookie requests are still same-origin only.

## Behavior

The mobile app's web build (`EXPO_PUBLIC_API_URL=http://localhost:3200 expo export --platform web`, served on :8099) against `PORT=3200 scripts/dev-local.sh` with the seed data, driven by Playwright at 390×844. Cross-origin from :8099 to :3200, so this also exercises the CORS path.

```

      email       | active | rotated
```

- Storage holds only the refresh token and user, never the access token.
- After the reload no refresh call was made, because the placeholder home screen calls no operation. The session refreshes lazily on the first call (covered by the unit tests); the clubs screen in the next PR will exercise it end to end.
- Afterwards I deleted the test `mobile_sessions` row and the `mobile-*` rate-limit rows.
